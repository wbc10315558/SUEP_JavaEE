# Java EE：Spring Cloud实验说明

​	为了帮助更高效地解决Spring Cloud服务部署中出现的问题，特制作本文档。

## 一、重要约定

### 服务端口

为了防止各个服务运行中使用相同的端口导致端口冲突报错，请遵守以下约定：

| 服务               | 端口号         | 如何自查                                                     | 如何修改成正确的                                             |
| :----------------- | :------------- | :----------------------------------------------------------- | :----------------------------------------------------------- |
| nacos 管理页面     | localhost:8080 | 正确启动nacos后，浏览器访问localhost:8080                    | 找到nacos安装目录下conf目录的application.properties，找到**nacos.console.port**字段，修改为8080随后重启nacos |
| nacos 节点         | localhost:8848 | 正确启动nacos后，在cmd中输入netstat -an，观察是否出现Listening 8848端口的条目 | 找到nacos安装目录下conf目录的application.properties，找到**nacos.server.main.port**字段，修改为8848随后重启nacos |
| DemoApplication    | localhost:8081 | 在IDE右上角打开DemoApplication的运行配置，观察是否有--server.port=8081的运行参数 | 修改或添加IDE运行配置，添加上这个参数                        |
| GatewayApplication | localhost:8082 | 在IDE右上角打开GatewayApplication的运行配置，观察是否有--server.port=8082的运行参数 | 修改或添加IDE运行配置，添加上这个参数                        |

## 二、常见疑问

### 为什么一个Spring程序要用到Nacos？

​	也许你会注意到，我们的Spring程序启动，需要参考application.yml配置文件中的参数。如果我们因为某些需要，修改了application.yml的参数，或是添加了一些额外的配置，我们不得不重新启动Spring程序以让新的配置生效。然而，在实际生活中，我们很少看到大型公共网站会因为修改配置而重启对外提供网页服务的程序。这里就用到一项技术，动态注入配置文件，即在不停止、不重启服务端程序的前提下，实时改变一些程序配置。

​	比如，我们的网页是一个信息管理系统，用户通过账号和密码访问系统，存储用户的用户名和密码等信息需要用到数据库，Spring当然需要知道数据库在哪，所以数据库的IP地址，端口号，用户名和密码等信息会写在Spring程序的配置文件中。假如数据库突然崩溃，我们就需要更换到备用数据库。如果没有动态注入技术，我们需要把配置文件中崩溃的数据库的地址更换为备用数据库的地址。要想让备用数据库生效，又得重启Spring程序。这在大型复杂的网页中，需要很长的时间。从用户的视角看，由于关闭了Spring程序，用户长时间根本无法访问网页的前端，作为服务端的你根本没机会安慰用户。如果有了动态注入技术，那么我们就可以实施一种代价更小的替代方案，即通过动态注入，在不停止Spring程序的情况下，修改数据库的相关信息，重定向到备用数据库，这样能在短时间内解决问题。从用户的视角看，网页并没有崩溃，只是短时间内登录不进去罢了，这相对于长时间整个网页无法访问好得多。

​	我们把与动态注入的配置文件相对的概念叫静态配置文件（在Spring程序中，application.yml是典型的静态配置文件）。根据业务的一般需求，我们通常把Spring程序运行全程都不会变化的配置项，或者需要变动但是在Spring程序运行伊始必须为某一个值的配置项，放在静态配置文件中，而把暂时无法确定初始值，或者运行期间需要中途变动的配置和参数，采用运行的时候动态注入的方法配置。

​	需要指出的是，Spring正在执行的配置有且仅有一个，但是配置文件可以有很多个。刚才提到的静态配置文件和动态配置文件，就是其中一种分类，在静态配置文件中也可以细分。不同的配置文件，对同一个配置项的设定可能不一样。如果说配置文件告诉Spring做什么的话，那么假如不同的配置文件告诉Spring做的事情不一样，Spring最终会听谁的呢？针对各配置文件中有冲突的配置项，决策遵循以下原则：

1. 动态配置优先于静态配置
2. 专用配置优先于全局（公共）配置

优先级规则之间亦有优先级，上述规则1优先于规则2适用。

​	动态配置注入有助于提高Spring框架的灵活性和便捷性，使得程序员可以对于不同的业务情况采取不同的配置。Nacos正是能够动态注入配置的软件，是这灵活性和便捷性的关键组成部分。

​	动态注入配置只是Nacos的一项次要功能，主要功能是对服务的管理和监控。按照安全设计，它只应当运行在内网。Spring Cloud是Spring框架的一个扩展功能，提供了与Nacos对接的支持。

### Nacos和Spring程序是怎么协同工作的？

1. Nacos服务先行启动。
2. 将动态配置导入Nacos。
3. 程序启动阶段，通过Spring Cloud会根据静态配置文件中的配置，尝试寻找正在运行的Nacos服务节点。
4. 找到节点后，Spring Cloud请求Nacos注入动态配置。
5. Nacos根据先前导入的动态配置文件，提供给Spring程序。
6. 程序对本地静态配置文件和动态注入的动态配置文件求并集，合并冲突的项取动态配置文件的值。
7. 程序根据合并后的配置启动服务并执行，但保持与Nacos服务节点的联系。
8. 程序监听Nacos服务节点发来的配置变更命令，当管理员在Nacos发布新配置文件时，实时进行变更。

​	以上就是Nacos和Spring程序协同工作过程。

### 为什么拷贝下来的项目，和老师给的原版略有不同？

​	本项目对老师的版本进行的优化，主要体现在：

1. 老师给的配置文件是一个压缩包，可以直接导入nacos，但是本项目将它们从压缩包中抽出来，添加了一些注释，方便理解。
2. 删除了一些本身就是默认值的配置项，减少了冗余信息。

### 如何部署本项目？

1. 首先自行下载并配置好nacos（要求【你的nacos文件夹】/conf/application.properties中的nacos.core.auth.enabled条目为true），nacos版本号应当大于3，打开cmd，将路径导航到nacos安装目录下的bin文件夹，运行startup.cmd -m standalone命令启动nacos（nacos启动要求secret key的，可以随便输入，但是第二次和第三次的secret key应当一致。
2. 打开浏览器访问localhost:8080/next，设置好用户名密码，找到平台管理 -> 命名空间，创建一个新的命名空间，注意，提示要求输入命名空间名称和命名空间ID，这两个都填写shiep。
3. 完成后转到配置管理，选择新建配置，第一个配置文件名写demo-dev，选择格式为YAML，在【项目文件夹】/src/main/resources文件夹下找到demo-dev.yml和gateway-dev.yml，将demo-dev.yml的内容复制进demo-dev，gateway-dev.yml的内容复制进gateway-dev。
4. 完成后点击发布，回到项目文件夹中。
5. 进入【项目文件夹】/src/main/resources文件夹，找到application.yml，将配置文件中的数据库用户名和密码、nacos用户名和密码换成自己的。
6. 完成之后，打开Intell IDEA，先关闭以前的项目，再在开始页面右上角点击“打开”，导航到项目文件夹，点击“选择文件夹”以打开。
7. 在IDE中打开pom.xml，右键点击“+添加为maven项目”，随后再次右键选择maven -> 同步项目以安装pom.xml中的依赖。如果你打开文件夹之后，IDE右下角自动弹出“找到maven依赖文件”的窗口，那就更方便了，点击加载即可一键完成依赖安装。
8. 编写启动配置，在IDE右上角，找到“当前文件”，点击下拉菜单，选择“编辑配置”
9. 点击左上角加号，新建一个类型为SpringBoot的启动配置，启动类为DemoApplication（要输入完整，如本项目为com.demo.DemoApplication），点击“修改选项”，找到“程序实参”，在新增的输入框中输入“--spring.application.name=demo --server.port=8081”，点击应用生效。
10. 点击左上角加号，新建一个类型为SpringBoot的启动配置，启动类为GatewayApplication（要输入完整，如本项目为com.gateway.GatewayApplication），点击“修改选项”，找到“程序实参”，在新增的输入框中输入“--spring.application.name=gateway --server.port=8082”，点击应用生效。
11. 启动DemoApplication和GatewayApplication，两个程序开始运行后，查看nacos后台检查这两个服务是否已经上线。
12. 进行后续的接口测试实验，要求使用apifox向localhost:8081发送四种不同的请求，观察后台数据库和返回的HTTP数据包是否符合预期。
